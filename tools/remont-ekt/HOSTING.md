# Перенос РЕМОНТ-ЕКТ на remontekt.ru

Этот пакет — статический сайт без сервера заявок, базы данных и счётчиков. Он сохраняет дизайн, тексты и оригинальные фотографии. Заявка остаётся черновиком в браузере: посетитель самостоятельно копирует и отправляет её на почту/в выбранный мессенджер. Отправка с сервера, журнал согласий и автоматическая доставка писем не реализованы.

## Перед загрузкой

1. Уточнить провайдера, доступ к панели и корневую папку домена. Выбрать размещение в РФ; подтвердить фактическую схему хранения и обработки персональных данных у владельца/провайдеров.
2. Сохранить действующий сайт, DNS-зону и почтовые настройки. Не удалять MX/TXT при смене A/AAAA. Устранить старый AAAA, если новый хостинг не обслуживает IPv6.
3. Создать сайт для remontekt.ru и www.remontekt.ru. Подключить сертификат для обоих имён с автоматическим продлением.
4. Проверить владельцем сведения, цены, права на фотографии/отзывы, подтверждение заявления о самой большой барной стойке. Никакие тексты этого пакета не заменяют проверку фактических обстоятельств.
5. Подтвердить уведомление Роскомнадзора/применимость исключений, фактическую локализацию первичного сбора, регламент почты, сроки удаления и доступ сотрудников. Размещение политик само по себе не закрывает эти обязанности.

## Загрузка

Загрузить содержимое каталога сайта в document root домена. Все ссылки относительные. Выбрать ОДИН вариант настройки сервера:

- Apache 2.4: использовать `.htaccess`, если провайдер разрешает mod_rewrite, Headers, Options и ErrorDocument. Если ошибка 500, проверить журнал и разрешённые директивы; нельзя оставлять сайт с ошибкой. Сначала проверить HTTPS, затем включать редиректы.
- Nginx: `.htaccess` не применяется. Адаптировать `nginx.conf.example`, пути сертификатов и корень сайта. Проверить `nginx -t` до перезагрузки. Не добавлять `add_header` внутри location без повторения общих защитных заголовков: это сбрасывает их наследование.
- Управляемый хостинг: настроить аналогичные правила в панели провайдера. Этот пакет не предполагает, что используемый провайдер поддерживает Apache или Nginx.

Не публиковать HOSTING.md, SHA256SUMS и nginx.conf.example. Они входят в пакет для администратора; конфигурации ограничивают HTTP-доступ, но файлы предпочтительно хранить вне document root. Страница 404 должна возвращать именно HTTP 404, без перенаправления на главную с кодом 200.

В новом домене уже подготовлены canonical, Open Graph, JSON-LD, robots.txt и sitemap.xml. В макете на GitHub установлен noindex,follow, чтобы он не конкурировал с рабочим доменом; остальные макеты не затронуты. На рабочем домене index,follow включён. Не включать индексацию у ещё одной публичной копии.

CSS имеет версию `launch-1`, JS — `mail-1`; после изменения нужно обновить версии. Для нового файла фотографии использовать новое имя либо очищать кеш: оригиналы не имеют content hash в URL. HTML не кешировать надолго. Включить gzip/Brotli средствами провайдера; JPEG/WebP/WOFF2 повторно не сжимать.

Политика CSP подготовлена в режиме report-only без внешнего коллектора отчётов. Проверить консоль браузера, затем перевести в Content-Security-Policy. Добавление аналитики, виджетов или API требует пересмотра политики и документов. HSTS включать после стабильной работы HTTPS; не добавлять includeSubDomains/preload без проверки всех поддоменов.

## Проверка после загрузки

- https://remontekt.ru/ — 200, корректный сертификат; все локальные ресурсы — 200.
- http://remontekt.ru/, http://www.remontekt.ru/, https://www.remontekt.ru/ и /index.html — один постоянный переход на https://remontekt.ru/ (без циклов).
- /несуществующая-страница — 404; каталог assets не показывает список файлов.
- robots.txt, sitemap.xml, favicon.svg, документы и frozen-версия согласия — доступны; sitemap содержит рабочий домен.
- Телефоны, почта, карты, АПГРЕЙД, меню, проекты, фильтры, отзывы, клавиатура и модальные окна работают на iPhone/Android/десктопе.
- Согласие изначально не отмечено; подготовка черновика не отправляет данные; копирование и возврат к редактированию работают. Реальное тестовое письмо отправить владельцу по согласованному сценарию; сохранить полученное согласие и проверить доставку.
- Проверить защитные заголовки, компрессию, кеширование; CSP не блокирует необходимые ресурсы; никаких ключей/паролей в публичных файлах.
- Проверить /404.html без JS, страницы документов и основной контент с отключённым JS.

## Поиск и локальная выдача после запуска

Подтвердить владение доменом в Яндекс Вебмастере и Google Search Console через доступ владельца; передать sitemap, проверить индексацию и назначить регион Екатеринбург в доступных настройках. Обновить сайт на карточках Яндекс Бизнеса и 2ГИС, сверить офис, телефоны и часы работы. JSON-LD содержит фактический офис, а не домашний юридический адрес ИП; координаты и рейтинги не придуманы.

Сервисные и кейсовые страницы, новые SEO-тексты, FAQ и изменения контраста/горизонтальной композиции не добавлялись: они затрагивают запрещённые в этом задании тексты или дизайн. GEO/AI-видимость не требует «магического» файла и не гарантирует цитирование; здесь улучшена доступность реальных сведений и контента в HTML.

Аналитика не установлена. Если владелец выбирает Метрику, сначала определить параметры, обработчиков и места хранения, обновить документы и реализовать соответствующий выбор до запуска необязательного отслеживания. Баннер о cookie не нужен только потому, что сайт существует; проверять фактические cookies/хранилища и обработку данных.

## Восстановление

Сохранить архив и SHA256SUMS этой версии. При сбое вернуть предыдущую корневую папку и конфигурацию сервера. Не откатывать почтовую DNS-зону вслепую.

Регенерация из репозитория: `node tools/remont-ekt/prepare.cjs --output /absolute/path/site`. После изменения данных проектов/отзывов запустить этот скрипт и проверить разницу HTML. Новую редакцию согласия публиковать отдельным файлом, не перезаписывая архивную.

## Отправка заявок на REG.RU

Требуются PHP 8.1+ и рабочий локальный `mail()`. В текущем аккаунте REG.RU настроен `/usr/sbin/sendmail -t -i -f info@remontekt.ru`; письмо использует From info@remontekt.ru и фиксированный To dom196@list.ru. Reply-To задаётся только для проверенного email посетителя. Обработчик не переопределяет конфигурацию почтового транспорта.

Приватные ключ и технические записи находятся в `/var/www/u3679966/data/.remontekt-requests`, вне публичной папки, с правами 0700/0600. При другом расположении релиза задайте серверную переменную REMONTEKT_FORM_DATA_DIR с абсолютным приватным путём. Не переносите каталог в document root и не включайте его в публичный архив. В журнале хранятся контрольные суммы, номер, время и статус; поля заявки доставляются только в письмо. Подтверждения старше 30 дней и счётчики старше суток очищаются при последующих запросах отправки.

Согласие для отправки: `consent-2026-10-14-mail.html`; старая версия `consent-2026-10-14.html` неизменна. Полученное письмо содержит согласие и контрольную сумму документа. Сохраняйте его с обращением и соблюдайте сроки удаления и права субъекта. `mail()` подтверждает принятие письма транспортом; окончательную доставку контролирует владелец почты (включая папку Спам). Если сервер вернул отказ или сеть оборвалась, интерфейс сохраняет поля. Повтор того же номера не создаёт второе письмо.

Форма принимает только основной HTTPS-домен, проверяет Origin и подписанный токен, поля/согласие, скрытое поле, частоту и повторы. Ограничения: 1 отправка в минуту, 5 в час, 10 в сутки для одного сетевого адреса; 150 в сутки суммарно. Для пользователей за общим NAT лимит может быть общим; остаются прямые контакты. Ни форма, ни обработчик не являются общей системой рассылок.
