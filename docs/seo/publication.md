# Завершение публикации и IndexNow

`node tools/remont-ekt/prepare.cjs --output /absolute/export` формирует статический сайт, канонические страницы, robots, sitemap и CSP. Даты sitemap теперь берутся из фактических `published`/`modified` материалов и `site-dates.json`, а не из одной общей даты. Изменение скрипта или повторная сборка сами по себе не обновляют дату контента. При существенной правке материала поставить реальную modified; новая статья получает фактическую published. Hubs получают максимальную дату своих материалов. Генератор видимой даты статьи и Article.dateModified использует те же исходные данные.

## Последовательность релиза

1. Собрать/проверить экспорт. При переносе на REG сохранить рабочие правила обратного прокси: универсальное `%{HTTPS}` может создать цикл. Новую CSP взять из экспорта и применить с действующей конфигурацией REG. Сохранить все доказательства владения и архивные согласия.
2. Сделать резервную копию и опубликовать новую версию; проверить SSL, HTTP-статусы, все HTML-хеши, CSP и работу формы. Не заменять приватные данные заявок публичным каталогом.
3. Выполнить финальный post-deploy hook (ниже). Он сам проверяет опубликованные страницы перед отправкой. Его можно вызывать из используемого сценария деплоя после успешного переключения корня; из одной сборки без публикации он не отправит неподтверждённую версию.

```sh
node tools/remont-ekt/publish.cjs --site /absolute/export --state /absolute/private/indexnow-state.json
node tools/remont-ekt/publish.cjs --site /absolute/export --state /absolute/private/indexnow-state.json --key-file /absolute/export/EXISTING_PUBLIC_KEY.txt --submit
```

`EXISTING_PUBLIC_KEY.txt` в примере — имя реального уже опубликованного файла доказательства; копировать существующий ключ, не создавать новый при каждом релизе. Сам ключ является публичным подтверждением, не паролем от аккаунта. Настоящий файл сохранён на текущем домене.

Первая команда — dry-run, без сетевых запросов и записи подтверждённого состояния. Вторая — отправка после проверки. Не размещать состояние, lock или JSONL-журнал в document root, исходниках или публичном архиве. Каталог состояния защищать 0700; файлы создаются 0600. Инструмент запрещает состояние внутри текущего экспорта, включая символьные ссылки; администратор также должен исключить любые другие публичные корни.

## Что делает hook

- Сверяет канонические HTTPS-URL sitemap, отсутствие query/hash, редиректов и noindex; разрешены только маршруты текущего сайта.
- Сравнивает смысловой отпечаток опубликованного содержимого, метаданных, JSON-LD, изображений и ссылок с последним принятым состоянием. Замена cache-version скрипта, class или CSS не создаёт новую отправку сама по себе.
- В первый запуск включает текущие адреса, при следующих — новые, изменённые и удалённые. Для удалённых проверяет настоящий HTTP 404/410; при переводе страницы в noindex с HTTP 200 требуется отдельное рассмотрение, такое удаление инструмент автоматически не подтверждает.
- Проверяет реальный HTTP 200 и побайтное совпадение HTML с экспортом для изменённых адресов. Любое расхождение или запрещающий X-Robots-Tag (noindex/none, включая указание робота) останавливает отправку. Проверяет доступность файла ключа и его содержимое.
- Блокирует параллельные запуски через private lock. После аварийного завершения осмотреть процесс/состояние и удалить только его оставшийся lock; инструмент не снимает чужие блокировки автоматически.
- Отправляет один пакет на официальный https://api.indexnow.org/indexnow, журналирует время, адреса и статус. HTTP 200 означает получение уведомления; HTTP 202 — получение с ожидающей проверкой ключа. Оба не означают индексацию.
- Только после 200/202 атомарно сохраняет новые отпечатки; повтор неизменившегося релиза ничего не отправляет. При ошибке состояние не подтверждается, нет бесконечного цикла автоматических повторов.

При 429 соблюдать Retry-After, при 403/422 проверить ключ/URL, при 5xx/сетевой ошибке повторить позже после проверки сервиса. Ошибка уведомления после успешного релиза не требует отката исправного сайта. Сначала проверить журнал; не повторять принятую неизменившуюся пачку вручную. Состояние хранить при следующих релизах и откатах; не обнулять ради повторных отправок.

Google Indexing API для обычных страниц не используется. IndexNow не требует подключения Search Console/Вебмастера, не заменяет sitemap и не гарантирует обход или позиции. Инструмент уведомляет поддерживающие протокол поисковые системы; Google-подключение этим не заявляется.

Тесты: `node --test tools/remont-ekt/publish.test.cjs` — dry-run, первая отправка/повтор, HTTP-ошибка без подтверждения, несоответствие опубликованной версии, удаление, чужие URL/query, блокировка, приватность и символические ссылки, фильтрация правок ресурсов.

Документация протокола: https://www.indexnow.org/documentation .
