# Аналитика: подготовлено, сбор отключён

На 22.10.2026 идентификаторы Метрики и GA4 не предоставлены. `analytics-config.js` содержит `enabled:false`, `metrikaId:null`, `ga4Id:null`. На сайте нет загрузчика сторонних SDK, новых cookies, очереди событий или записи выбора в localStorage. Подключён только локальный адаптер. Передача событий в реальные кабинеты не выполнена и не заявляется.

## Подготовленные события

| Событие | Источник | Значение |
| --- | --- | --- |
| request_open | Открытие существующего диалога | Интерес; не заявка |
| form_submit | Валидная отправка, принятая клиентским обработчиком | Попытка; не подтверждение |
| generate_lead | Только HTTP ok и JSON `ok:true` от обработчика | Успех серверного приёма; не доказательство доставки почтой |
| contact_phone | Ссылка tel: | Контактный переход; не подтверждённый звонок |
| contact_email | Ссылка mailto: | Контактный переход; не отправленное письмо |
| contact_telegram | Ссылка t.me / telegram.me | Переход; не сообщение |
| contact_whatsapp | Ссылка wa.me / api.whatsapp.com / web.whatsapp.com | Переход; не сообщение |

В Метрику адаптер передаёт `ym(id,'reachGoal',name,{page_path})`. В GA4 — `gtag('event',name,{send_to,page_location,page_referrer:'',page_path})`. Дополнительные аргументы `track()` игнорируются. Имя, контакт, сообщение, номер заявки, query string, hash, исходный referrer и значения полей не читаются адаптером. В SDK провайдеров возможен собственный автоматический сбор: его нужно отдельно проверить при подключении.

Разрешены только заранее перечисленные имена событий. Адаптер работает исключительно на remontekt.ru, при enabled:true и явном `window.RemontAnalytics.setConsent(true)`. До согласия события отбрасываются, после отзыва адаптер прекращает передачу. Сам адаптер не загружает и не останавливает внешние SDK — это ответственность будущего слоя подключения/управления согласием. Наличие одной этой функции не означает готовую систему управления согласием.

## После создания счётчика

1. Выбрать нужный сервис: подключать оба только при реальной необходимости. Получить настоящий ID; не подставлять демонстрационные номера. Для начала оставить enabled:false.
2. Проверить применимые требования к персональным данным, обработчиков, размещение и передачу данных, сроки хранения и документы. Согласие на заявку не подменяет согласие на необязательное отслеживание. Текущие архивные согласия не менять.
3. Подключить SDK и отдельное управление согласием: до выбора — никаких SDK-запросов/пингов; отказ — не загружать; отзыв — остановить соответствующий SDK, отключить отправку и обработать его хранилища. Выбор должен быть доступен для повторного изменения. Текущий внешний вид не изменялся: этот интерфейс пока не установлен.
4. Для GA4 отключить ненужное автоматическое отслеживание форм и расширенные/рекламные функции, задать чистый page_location без query/hash, пустой referrer и проверить фактические сетевые запросы, включая автоматические page_view. Для Метрики рассмотреть defer:true и явный hit с чистым URL, отключить Вебвизор, автосбор форм и ненужные функции. Не включать Advanced Matching/User-ID/передачу контактных данных.
5. Внести ID в analytics-config.js; разрешить только необходимые домены SDK/collect в CSP; обновить версии ресурсов и текущие документы. Включить enabled только вместе с проверенным согласием. Принудительная CSP сейчас допускает лишь собственные скрипты и подключения, поэтому добавление одного ID недостаточно.
6. В Метрике создать цели с точными именами. В GA4 отметить generate_lead ключевым событием; остальные события анализировать отдельно. Не считать каждую попытку успешной заявкой.
7. Проверить отсутствие дублей и реальный приём в Метрике/GA4 Realtime/DebugView. Тестовые события отделить от рабочих; убедиться, что ошибка/тайм-аут не создаёт generate_lead, повтор не удваивает результат и заявка продолжает работать при заблокированной аналитике.

Использованы только функции-приёмники SDK в тесте, реальная доставка в кабинеты не проверялась. Реальные письма не отправлялись.
